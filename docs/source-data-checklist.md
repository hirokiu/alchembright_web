# 次工程で必要なデータ

今回の公開調査では認証情報やバックアップを受領していません。次工程で以下を準備します。認証情報は文書・チャット・Gitへ書き込まず、必要な環境の安全な方法で設定します。

## WordPress

- 管理画面「ツール → エクスポート → すべてのコンテンツ」のWXR XML。出力日時・対象範囲を併記。
- DB全体のバックアップと復元手順。原本文、投稿状態、コメント、メタデータ、設定との照合用。
- `wp-content/uploads/` 全体。原寸・縮小版・回転/トリミング版も含む。
- uploads以外に置いた画像、PDF、ダウンロード資料。テーマ、CSS、プラグイン設定のバックアップ。
- パーマリンク設定、サイトURL/home、タイムゾーン、カテゴリ基底、転送設定、公開状態別/種類別の件数。
- コメント/トラックバック、予約・下書き・非公開・保護記事の保管と公開方針。

## Movable Type・旧ホスト

- MTエクスポート、DB、生成済みHTML、テンプレート、画像ディレクトリ、旧.htaccess等。存在する範囲でよいが、不足は記録する。
- `hrk-up.net/mt/balog_images/`、`www.balog.jp/~hiro/mt/archives/`、`note.alchembright.com`、`dev.balog.jp` の所有/管理状況と利用可能なバックアップ。
- 旧entry ID・basename・旧URLとWP IDの対応記録、過去の移行スクリプトやログ。
- 元の文字コード、日時の扱い、2006/2007等のAPIにない年の記事が元々存在したか。

## 配信環境

- Webサーバー種別、OS、静的ファイル配置先、TLS、DNSの管理範囲。
- SSH/SFTP等の利用可能な配置方法、ステージングURL、リリース切替/復旧方法。
- 同一ホスト継続か別ホスト移行か、旧ドメインへの301設定の可否。
- 画像等の総容量。Gitへの収容が難しい場合はLFSや別の保存先を比較し、原本と配信物の再現性を維持する。

## 受領時の記録

各データについて取得日時、出所、件数/サイズ、SHA-256、公開可否、保管場所、復元確認結果を記録します。バックアップには非公開情報が入りうるため、リポジトリがprivateでもそのままコミットしません。
