## 接続手順

1. まず既存プロパティを管理しているGoogleアカウントに切り替える。または所有者に「設定 → ユーザーと権限」から閲覧するアカウントを追加してもらう。パフォーマンス参照だけなら制限付き権限で足りる。
2. 既存プロパティがない場合、URLプレフィックス `https://www.alchembright.com/` を追加する。提示されたHTML確認ファイルを `public/` に配置、または指定の確認メタタグをレイアウトに追加して公開・確認する。確認用トークンはGoogleが実際に発行したものを用いる。
3. 全サブドメインをまとめる場合はドメインプロパティ `alchembright.com` を追加し、提示されたDNS TXTで確認する。wwwのCNAMEや他サービスのAレコードは変更しない。既存のnote/dev等が混ざるので、基準値はwwwのページURLに絞る。
4. 所有権確認が済んでも過去データがすべて遡及取得できるとは限らない。表示される取得可能期間・欠損を記録する。確認用ファイル/TXTはその後も保持する。

## 接続後の取得手順

「検索パフォーマンス → 検索結果」で検索タイプをWebに固定し、国・デバイスは全件とする。直近28日と過去3か月それぞれについて、取得日時、プロパティ、フィルター、実際の開始日・終了日、データの最終更新日を保存する。日付はSearch Consoleの太平洋時間基準で扱い、暫定データを含めたか明記する。3か月は一律90日に置き換えない。

各期間で以下を取得する。

- フィルターなしの全体クリック数、表示回数、CTR、平均掲載順位。
- 検索クエリ別とページ別の4指標をそれぞれエクスポート。
- 指名検索フィルターを適用した全体指標、クエリ別、ページ別。
- 同じ正規表現の「一致しない」を使った非指名検索の指標。取得条件を揃える。

指名検索の初期候補（大文字小文字を区別しないカスタム正規表現）：

```text
上松[ 　]*大輝|うえまつ[ 　]*ひろき|hiroki[ 　._-]*uematsu|uematsu[ 　,_-]*hiroki|hiroki[_ -]?u|alchembright
```

これは表記の分類であり検索意図の確定ではない。同名選手や別研究者への検索も混ざり得るため、実際のクエリを見て「本人ブランド表記」「同名で意図不明」を別途注記する。スペルミスの追加は実測を見て行う。

匿名化されたクエリや行数制限により、クエリ表の合計は全体と一致しないことがある。指名と非指名の差分を匿名クエリの帰属として推定しない。CTRは合計クリック数÷合計表示回数で計算し、行CTRの単純平均を使わない。平均順位も行の単純平均にしない。

UIエクスポートで足りない場合はSearch Console APIを読み取り専用 `webmasters.readonly` で接続する。Search Analyticsの全体・query・pageを別々に取得し、必要に応じてページングする（最大25,000行／リクエスト）。APIも全クエリの完全取得を保証しない。認証情報・生の検索クエリはpublicリポジトリへ置かず、非公開の保存先で管理する。
