## 保存場所と台帳

1. 原本：WordPress uploads、MT画像フォルダ、ローカルバックアップを出所別に、そのまま別の非公開バックアップ領域で保管。元ファイル名・フォルダ階層・取得日時を保持し、SHA-256を採る。読み取り専用の作業元とし、別媒体にも複製する。
2. 作業用：非公開の場所で候補一覧・縮小コンタクトシート・確認メモを作る。撮影位置などのEXIFや人物が含まれうるため、一覧も公開しない。
3. 配信用：確認済み画像だけ public/media/imported/ に保存。サイト共通の背景・ロゴ類は public/media/site/。原本全体のコピーやPPTX埋め込み画像の一括公開はしない。
4. 対応表：既存 migration/mappings/media-map.csv を継続使用。元URL、記事ID、新URL、ハッシュ、サイズ、形式、回収状態、根拠を記録する。画像URL変更は許容し、旧URLを来歴として残す。

同じバイト列はハッシュで同一判定できる。ファイル名や見た目だけでは確定しない。原寸・縮小版・トリミング版は別資産として比較し、元画像が同じ場合にも各旧URLの対応を残す。現在の回収スクリプトはURLごとの配信先を作るため、別URL間での物理的重複排除は行わない。

## 確認の順番

- 最初に背景・アイキャッチ・よく読まれる記事の画像を確認し、次に年代順に未回収を消し込む。
- 候補を元URLのパス、ファイル名、寸法、日時、記事内容、サムネイルと比較。一致・候補・未発見を区別し、候補段階では登録しない。
- 公開用コピーの向き、色、破損、人物・住所・位置情報・顧客名・画面内の機密を確認。撮影者の許可と第三者情報の公開可否は分けて扱う。
- EXIF削除・縮小などが必要なら配信用コピーだけを加工し、変換内容と原本／配信物の両ハッシュを記録する。今回は画像加工を実施していない。
- 提供ロゴは132×132の小画像。既存レイアウトは保持し、拡大表示は見送る。大きく使用する場合は高解像度版かベクター原稿を探す。

## WordPressからの回収と反映

WXRだけでは画像本体を保管できないため、サーバーの wp-content/uploads/ 全体と、uploads外の旧画像・テーマ資産も別途確保する。DB/WXRから添付ID、親記事、alt、キャプション、説明、元寸法、派生画像、公開状態を照合する。WXR/DBの自動インポートは現ツール未対応。

登録は docs/migration-workflow.md の recover-media.mjs を使用する。これは形式検査とコピー・対応表更新を行うが、見た目・機密・EXIFの審査はしない。対応表にない新規URLは出所と利用記事を確認してから追加する。

回収後は新しいステージへ再インポートし、差分確認後にpromote、ビルド、migration:verifyを実行する。画面で画像表示、縦横比、リンク先原寸、スマートフォン表示を確認する。未回収127件は現時点で継続。元WordPressやバックアップの削除、DNS切替は行わない。

## タグとMarkdownの次工程

MTの本文・追記・カテゴリ・タグを別項目として解析し、タイトルと日時に加え本文・basenameも使ってWP記事IDへ対応付ける。バックアップのPublish以外、コメントの個人情報、対応しない記事は自動公開しない。WordPress原本と現MarkdownでタグIDが一致するかを先に調べ、MTとの差を復元候補として記録する。復元は再現可能な対応表で行い、Markdown整形とは別の差分として確認する。
